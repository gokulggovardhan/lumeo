# Privacy Analytics

Lumeo uses first-party, privacy-preserving analytics to measure genuine audience traffic and PDF-tool reliability. Document processing remains browser-local.

## Production architecture

- Public UI uses `components/analytics/AnalyticsProvider`.
- Do Not Track and the public `public_analytics_enabled` setting remain authoritative.
- The browser sends approved event fields to same-origin `POST /api/analytics`.
- The route creates random first-party visitor and 30-minute session tokens as HttpOnly cookies.
- Raw cookie tokens are never stored in analytics rows. The server stores only HMAC-SHA256 pseudonymous visitor/session keys.
- Approximate geography is read server-side from Cloudflare visitor request metadata.
- Raw IP addresses are used only transiently to derive a pseudonymous rate-limit key and are never stored.
- Lumeo production browser tests are marked `synthetic`; known automation is classified separately.
- Admin Analytics defaults to `real_audience`, so synthetic tests and reliably identified automation do not inflate genuine visitor/page-view/location metrics.
- Legacy schema-v1 events remain historical/unverified and are not promoted into verified schema-v2 audience totals.

## Event allowlist

Approved events:

- `page_view`
- `tool_opened`
- `processing_started`
- `processing_succeeded`
- `processing_failed`
- `processing_cancelled`
- `download_started`

Analytics failures never block PDF work or downloads.

## Identity and sessions

The server sets:

- `lumeo.analytics.visitor.v2`: random first-party visitor token, up to 90 days.
- `lumeo.analytics.session.v2`: random first-party token with a sliding 30-minute lifetime.

Only HMAC-pseudonymized derivatives are persisted in `analytics_events`. The raw tokens are HttpOnly and are not returned to Admin Analytics.

"Unique Visitors" therefore means distinct pseudonymous first-party visitor identities, not guaranteed distinct physical people. "Sessions" means distinct 30-minute first-party browsing sessions.

## Geography

Geography comes only from Cloudflare request metadata derived from the visitor's network IP:

- Country
- State/Region
- City, when Cloudflare resolves it

Cloudflare datacenter/POP location (`cf.colo`) is never used as visitor geography.

A full Top Locations row requires genuine City + State/Region + Country. If one or more levels are missing, the page view remains in total traffic but is counted under **Unknown Location** rather than guessed.

No browser geolocation permission, GPS coordinate, precise street address, or external IP-geolocation service is used.

## Traffic integrity

Schema-v2 traffic classes are:

- `real_audience`
- `synthetic`
- `known_bot`
- `suspected_automation`

Lumeo Playwright production checks explicitly send the synthetic marker. Verified Cloudflare bots and a conservative known-bot user-agent list are classified separately. Ambiguous traffic is not silently rewritten to another city or country.

Admin Analytics exposes a traffic-scope selector and defaults to Genuine audience.

## Data collected

Only approved fields are accepted:

- event name
- known public tool slug when relevant
- pseudonymous visitor/session keys
- event time generated by the database
- bounded processing duration
- coarse input/output size buckets
- coarse device/browser/OS labels
- boolean success state
- approved generic error category
- approved conversion stage for failures/cancellations
- safe page path without query strings/fragments
- trusted approximate Cloudflare country/region/city
- traffic class/reason

## Data explicitly not stored

- PDF/document/image files
- filenames or output names
- document contents or extracted text
- thumbnails
- exact file sizes
- raw IP addresses
- raw visitor/session cookie tokens
- GPS coordinates or precise addresses
- emails or authenticated user IDs in public analytics
- passwords, access tokens, refresh tokens, or analytics secrets
- full user-agent strings
- query-string values
- document metadata

## Security boundaries

The database table keeps RLS enabled and is not directly readable/writable by anonymous visitors.

Trusted writes use `public.record_trusted_analytics_event(...)`. The RPC:

- requires the private ingest secret through the server-to-Supabase request header,
- validates the event/tool allowlist,
- validates pseudonymous identity format,
- enforces bounded rate limits,
- derives `occurred_at` inside PostgreSQL,
- validates safe page paths,
- accepts trusted geography only from the server route,
- deduplicates only near-identical event/tool/page-path events inside the same session,
- never accepts arbitrary metadata or document fields.

Admin reads use authenticated aggregate RPCs. The primary verified reader is:

`public.get_admin_verified_analytics(p_start_date, p_end_date, p_traffic_scope)`

Recent activity uses:

`public.get_admin_recent_analytics_events_v2(p_limit, p_traffic_scope)`

They require an active owner/admin/analyst membership and never expose visitor/session keys or raw IP addresses.

## Location reconciliation

For every date range and scope:

`Known Location page views + Unknown Location page views = total Page Views`

This invariant is checked by the application parser. Complete geography is never allowed to disappear from totals just because it cannot be displayed as City/State/Country.

## Do Not Track

When `navigator.doNotTrack === "1"`, optional analytics is disabled in the browser. When the public analytics setting is absent, false, or unavailable, event collection is disabled.

## Privacy/legal note

This architecture deliberately avoids document data, raw IP retention, precise location, and invasive fingerprinting. Product privacy disclosures must stay synchronized with implementation, and jurisdiction-specific legal requirements should still receive appropriate review.
