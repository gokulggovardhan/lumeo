# Privacy Analytics

Lumeo uses first-party, privacy-preserving product analytics. PDF/document
processing remains browser-local; analytics never receives document content.

## Current Architecture

- Public UI uses `AnalyticsProvider` and respects Do Not Track.
- The browser sends only approved product-event fields to
  `/api/analytics/event` on the same Lumeo origin.
- The browser does **not** send city, region, country, raw IP, GPS coordinates,
  or a visitor/session database identifier.
- The Cloudflare-hosted server route reads Cloudflare's inbound visitor
  geolocation (`request.cf.city`, `region`, `regionCode`, `country`).
- `request.cf.colo` is never visitor location; it is the Cloudflare
  datacenter code and is deliberately ignored.
- The route uses HTTP-only first-party random tokens for a bounded visitor
  identity and rolling 30-minute session.
- Raw cookie tokens are HMACed server-side; only 43-character pseudonymous
  keys are stored. Raw IP is used only transiently as HMAC input for abuse
  throttling and is never persisted or sent to Supabase.
- Schema-v2 events are written through the secret-protected
  `record_server_analytics_event_v2` RPC.
- Admin traffic reads only verified schema-v2 aggregates by default.
- Schema-v1 rows remain historical/legacy context and are not promoted into
  verified visitor or geographic metrics.

## Genuine Location

"Genuine location" means the approximate geographic result Cloudflare supplies
for the visitor's public IP. It is not GPS and cannot guarantee physical
location.

When available, analytics may retain:

- city
- state/region
- region code
- country code
- a source marker (`cloudflare`)
- a precision marker (`city`, `region`, `country`)

No browser geolocation permission is requested. No exact coordinates or street
address are collected. No fallback city, server region, Worker region,
Cloudflare POP/colo, or guessed country is substituted.

A complete Top Location requires city + region + country. Incomplete or missing
geography remains genuine traffic but is aggregated as **Unknown Location** in
the full-location view.

## Audience Definitions

- **Page View**: an approved `page_view` event generated by a real public
  page/navigation, not an HTTP request for assets or APIs.
- **Unique Visitor**: a distinct bounded first-party pseudonymous visitor key
  among page-view events in the selected range.
- **Session**: a distinct rolling 30-minute first-party session key among
  page-view events in the selected range.
- **Known Location Page View**: a page view with Cloudflare-supplied city,
  region, and country.
- **Unknown Location Page View**: every other verified page view.

For every selected period:

```
Known Location Page Views + Unknown Location Page Views = Total Page Views
```

## Traffic Classification

Verified audience metrics default to `real_audience`.

Lumeo separates traffic only with reliable evidence:

- `synthetic`: Lumeo-controlled production browser certification marked by
  the production Playwright context.
- `known_bot`: Cloudflare explicitly marks the request as a verified bot.
- `suspected_automation`: reserved for future evidence-backed classification;
  uncertain visitors are not guessed into this class.

Production browser tests therefore no longer inflate human traffic/location
analytics. Technical requests such as CSS, JavaScript, images, fonts, API
requests, health checks, and Worker requests never become page views because
they do not emit approved `page_view` events.

## Approved Event Lifecycle

Current Analytics Scope covers all 16 live PDF tools and public discovery
surfaces with:

- `page_view`
- `tool_opened`
- `processing_started`
- `processing_succeeded`
- `processing_failed`
- `processing_cancelled`
- `download_started`

Analytics delivery never blocks PDF processing or downloads.

## Data Collected

Only approved, bounded fields are accepted:

- event name
- public tool slug
- bounded pseudonymous visitor/session keys
- server timestamp
- page path without query/fragment
- coarse size bucket
- coarse device/browser/OS family
- generic success/error/failure-stage data
- approximate Cloudflare city/region/country when available
- coarse acquisition/referrer host and UTM labels
- traffic classification

## Data Explicitly Not Collected

- PDF/document files or contents
- filenames
- extracted text or thumbnails
- exact file sizes
- passwords
- emails or account IDs
- raw cookie tokens
- raw IP addresses in analytics storage
- full user-agent strings
- GPS/browser geolocation
- exact coordinates
- street addresses
- device fingerprints

## Do Not Track

If `navigator.doNotTrack === "1"`, the public analytics provider is disabled.
The server route also treats a `DNT: 1` request as non-collecting.

## Admin Analytics

The Admin Analytics page uses one IST date range for:

- Page Views
- Unique Visitors
- Sessions
- Known Location Page Views
- Unknown Location Page Views
- daily traffic trend
- Top Locations
- countries
- states/regions
- cities
- top pages
- real-audience tool activity
- device/browser/OS summaries
- recent verified activity

Top Locations use `City, State/Region, Country`. Country codes are expanded
for display where supported. Unknown Location is kept outside the city ranking
and displayed once at the bottom.

## Historical Data

Legacy schema-v1 rows are retained so historical event volume is not silently
deleted. Their older client/session/location semantics are not treated as
verified real-audience visitor geography. The Admin integrity panel reports the
legacy page-view count present in the selected range and the schema-v2 cutover
timestamp.

Historical suspicious US locations are never rewritten into guessed Indian
locations.

## Security

- No anonymous direct table access is granted for `analytics_events`.
- The public browser does not know the server ingestion secret.
- The ingestion RPC validates a Cloudflare-only secret header and input
  allowlists.
- Admin aggregate RPCs require an active owner/admin/analyst session.
- Raw visitor/session keys, raw IPs, and precise locations are never returned
  by Admin aggregate RPCs.
- Rate limiting uses pseudonymous request/session keys.

## Production Configuration

The runtime secret name is:

```
LUMEO_ANALYTICS_INGEST_SECRET
```

The same secret is hashed in `private.analytics_ingest_config` through the
service-role-only rotation function. The secret value itself is not stored
plaintext in Supabase.

## Testing

- server location unit tests
- no Cloudflare colo as visitor location
- no fake/default location
- missing/partial geo handling
- synthetic and verified-bot classification
- pseudonymous HMAC key shape

## Privacy Limitation

IP geolocation can resolve to an ISP gateway, mobile carrier exit point, VPN,
proxy, or nearby city. Lumeo displays the trusted Cloudflare result as supplied
and does not "correct" it by guessing.
