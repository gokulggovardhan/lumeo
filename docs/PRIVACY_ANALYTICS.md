# Privacy Analytics

Lumeo uses first-party, privacy-preserving product analytics to understand
audience activity and PDF-tool reliability. Analytics does not change the
browser-local document-processing architecture and does not send user documents
to the analytics backend.

## Current verified architecture

Public UI events flow through this trust boundary:

1. `components/analytics/AnalyticsProvider` checks the public analytics setting
   and browser Do Not Track.
2. `lib/analytics/client.ts` sends an approved event to the same-origin
   `/api/analytics` endpoint.
3. The server endpoint validates the event and derives:
   - a pseudonymous visitor key from a random first-party visitor token,
   - a pseudonymous 30-minute session key from a random first-party session
     token,
   - coarse device/browser/OS labels from the request user agent,
   - approximate city/region/country from Cloudflare request metadata,
   - a traffic class separating real audience, Lumeo synthetic tests, known
     bots, and suspected automation.
4. The endpoint calls only the protected
   `public.record_server_analytics_event(...)` RPC.
5. Supabase stores schema-v2 events and never receives the raw visitor/session
   cookie token or raw network address.
6. Admin pages read authenticated aggregate/recent-event RPCs. They do not
   directly select from `analytics_events`.

Legacy schema-v1 browser-submitted analytics remains retained as historical
evidence, but it is excluded from verified visitor/location metrics after the
cutover migration.

## Initialization and delivery

Analytics starts in a loading state while the public setting is resolved.
One-time page-view and `tool_opened` events wait for analytics to become
enabled before marking the local attempt as accepted.

When analytics is disabled or Do Not Track is enabled, optional product
analytics is skipped. PDF processing and downloads never wait for analytics and
analytics failures never block the document workflow.

There is no persistent event queue and no analytics use of `localStorage`.

## First-party visitor and session tokens

When optional analytics is enabled, the server may set:

- `lumeo_visitor`: random first-party HttpOnly token, up to 180 days.
- `lumeo_session`: random first-party HttpOnly token, about 30 minutes.

The raw token values are not stored in analytics tables. The server derives
one-way HMAC pseudonyms using a private server secret. The stored pseudonyms are
not account IDs and are not combined with email or authenticated user identity.

## Event allowlist

Verified analytics accepts only:

- `page_view`
- `tool_opened`
- `processing_started`
- `processing_succeeded`
- `processing_failed`
- `processing_cancelled`
- `download_started`

The protected database writer rejects unsupported events and unknown/disabled
tool slugs.

## Do Not Track

If `navigator.doNotTrack === "1"`, optional analytics is disabled in the
browser. The provider also disables analytics when the public setting is absent
or unavailable.

## Data collected

Depending on the event, schema-v2 analytics may store:

- approved event name,
- known public tool slug,
- server-derived visitor/session pseudonyms,
- event timestamp generated by the server,
- bounded processing duration,
- coarse input/output size buckets,
- coarse device/browser/OS family,
- approved generic error category and conversion stage,
- approximate city/region/country from Cloudflare when available,
- normalized public page path,
- traffic class used to separate real audience from tests/bots/automation.

## Data explicitly not stored in product analytics

- PDF/document/image files,
- filenames,
- document contents or extracted text,
- thumbnails,
- exact file sizes,
- raw IP addresses,
- precise coordinates or GPS,
- email addresses,
- authenticated user IDs,
- passwords,
- access/refresh tokens,
- full user-agent strings,
- query-string values,
- document metadata,
- raw first-party analytics cookie tokens.

A raw network address may be read transiently by the server only to derive a
one-way request-rate-limit key. The raw address is not sent to Supabase and is
not stored in product analytics.

## Location semantics

Location is approximate network-derived Cloudflare metadata, not device GPS and
not a precise address.

For the Admin **known-location page-view** metric, a page view must have
Cloudflare-verified country, region, and city. Anything less remains
**Unknown Location** rather than being guessed.

The verified aggregate enforces:

`Known Location Page Views + Unknown Location Page Views = Page Views`.

Location rankings are based on verified page-view rows, not on raw event volume.

## Real audience vs synthetic traffic

Schema-v2 traffic is classified as one of:

- `real_audience`
- `synthetic`
- `known_bot`
- `suspected_automation`

The Admin Analytics page defaults to `real_audience`. Lumeo-owned production
browser tests are marked synthetic by the production Playwright profiles so CI
traffic remains inspectable without inflating the business audience view.

## Size bucketing

Exact byte counts are not stored. File sizes are mapped to:

- `under_1mb`
- `1mb_to_5mb`
- `5mb_to_20mb`
- `20mb_to_50mb`
- `over_50mb`
- `unknown`

## Device, browser and OS classification

Only coarse labels are stored:

- Device: `desktop`, `tablet`, `mobile`, `unknown`
- Browser: `Chrome`, `Edge`, `Firefox`, `Safari`, `Other`, `Unknown`
- OS: `Windows`, `macOS`, `Linux`, `Android`, `iOS`, `Other`, `Unknown`

No screen resolution, installed-font list, canvas hash, hardware ID, or browser
fingerprint is collected.

## Database security

The verified foundation is defined by:

- `supabase/migrations/20260925113850_analytics_real_audience_foundation.sql`
- `supabase/migrations/20261004090000_verified_analytics_activation.sql`

The activation migration:

- upgrades `record_server_analytics_event(...)` to the current event/error
  vocabulary,
- requires a server-only ingest secret whose hash is stored in Supabase,
- keeps direct anonymous table access denied,
- revokes browser execution of the legacy `record_public_analytics_event(...)`
  writer,
- exposes `get_admin_verified_traffic(date,date,text)` only to authenticated
  active Admin roles,
- keeps recent schema-v2 events behind
  `get_admin_recent_analytics_events_v2(integer,text)`.

Admin aggregate readers never return visitor/session keys, raw cookies, raw IPs,
full user agents, filenames, document content, or precise coordinates.

## Admin Analytics

The default **Real audience** view includes:

- unique visitors,
- 30-minute sessions,
- page views,
- tool opens,
- known vs unknown location page views,
- country/region/city page-view rankings,
- page performance,
- processing started/succeeded/failed/cancelled,
- unreconciled starts,
- success rate,
- downloads,
- average successful duration,
- error/failure/cancellation categories,
- top tools,
- coarse device/browser/OS summaries,
- traffic-class separation,
- legacy-vs-verified integrity counts.

Date ranges use Asia/Kolkata calendar-day boundaries.

## PDF tool event lifecycle

All live PDF tools continue to use the approved lifecycle. Analytics is
non-blocking and does not change PDF engines or document fidelity.

A tool may emit `tool_opened`, then operation lifecycle events such as
`processing_started`, one terminal success/failure/cancellation outcome, and
`download_started` where applicable.

## Collection setting

The public setting remains:

`public_analytics_enabled`

Production collection occurs only when the setting resolves to enabled and Do
Not Track is not active.

## Validation

Relevant release gates include:

- `npm run verify:analytics`
- `npm run verify:supabase`
- `npm run verify:admin-auth`
- `npm run verify:control-center`
- unit tests,
- TypeScript,
- ESLint,
- Next build,
- Cloudflare/vinext Worker build,
- Chromium/WebKit/Firefox production browser tests.

Production certification must additionally confirm:

- Worker has `ANALYTICS_IDENTITY_SECRET` and `ANALYTICS_INGEST_SECRET`
  secret bindings,
- Supabase has the matching ingest-secret hash,
- new events are schema version 2,
- real audience and synthetic traffic are separated,
- location reconciliation is exact,
- legacy schema-v1 rows no longer increase.

## Privacy and legal review note

This design minimizes identity and document data, but privacy/legal requirements
vary by jurisdiction. Production analytics should continue to receive
appropriate legal review as the product evolves.
