## graphify

This project has a knowledge graph at graphify-out/ with god nodes, community structure, and cross-file relationships.

Install the tooling first — every rule below needs the `graphify` binary, which this provides:

```bash
pip install -r requirements-graphify.txt && python scripts/graphify_env_check.py
```

Rules:
- For codebase questions, first run `graphify query "<question>"` when graphify-out/graph.json exists. Use `graphify path "<A>" "<B>"` for relationships and `graphify explain "<concept>"` for focused concepts. These return a scoped subgraph, usually much smaller than GRAPH_REPORT.md or raw grep output.
- Read graphify-out/GRAPH_REPORT.md only for broad architecture review or when query/path/explain do not surface enough context.
- After modifying code, run `graphify update .` to keep the graph current (AST-only, no API cost).

### Regenerating the graph

`graphify-out/graph.json` is committed, so the environment that builds it is a property of this repo, not of your laptop. Two things change the output silently:

- **graspologic switches the partitioner.** graphify uses Leiden when graspologic imports and falls back to networkx Louvain otherwise. The two cluster the same graph differently, and nothing in `graph.json` records which one ran. If you have graspologic installed, your regenerated graph will disagree with the committed one and your PR will fight the refresh bot's. Never install the `[leiden]` or `[all]` extras — `[sql]` is the only one this repo wants.
- **The graphifyy version changes extraction.** Bump the pin in `requirements-graphify.txt` and regenerate together, never one alone.

Three separate things constrain the Python version, with three different strengths — a requirements file cannot pin an interpreter, so none of this comes from the spec alone:

| Where | Strength |
|---|---|
| `.github/workflows/graphify-refresh.yml` `python-version: '3.14'` | **Binding**, for CI only |
| `scripts/graphify_env_check.py` | **Warns** below 3.13; **fails** on graspologic or a version mismatch, at any Python version |
| `requirements-graphify.txt` | **Recommends** 3.13+ in a comment; enforces the graphifyy pin, nothing about the interpreter |

3.13 is the threshold that matters: graspologic's dependency marker is `python_version < "3.13"`, so at 3.13 and above it cannot be installed at all, even via `[all]`. Below that, the env check is the only thing standing between you and a different partitioner.

`.github/workflows/graphify-refresh.yml` regenerates the graph on merge to main and opens a PR, so routine staleness is not your problem — but a hand-regenerated graph from a mismatched environment is.

Do not commit `graphify-out/graph.html` (gitignored) or hand-edit anything under `graphify-out/`.
